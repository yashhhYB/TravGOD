TRAVGOD App Map

This is a take-home guide for your proof of concept. TRAVGOD is a single-page travel application that helps tourists discover destinations, stay safe with ScamSense, match with local guides using AI, and book trips using PayPal Sandbox.

Architecture Overview

The app is a vanilla JavaScript Single Page Application (SPA) bundled with Vite. It uses standard DOM manipulation, Leaflet for maps, and LocalStorage for state persistence.

  • index.html: Entry point. Loads Leaflet, Lucide icons, PayPal SDK, and main.js.
  • src/main.js: Main router. Switches between Landing Page and Destination Dashboard.
  • src/components/: Contains UI modules like LandingView.js, DashboardView.js, GuideDirectory.js, ChatWindow.js, PayPalModal.js, and MyTrips.js.
  • src/utils/: Contains the aiMatch.js algorithm and storage.js wrapper.

Reference Route: How Booking Works

Follow this path to see how a tourist books a guide from the dashboard to LocalStorage:

1. The Click (src/components/DashboardView.js)
When the user clicks "Book Guide" on a guide card, the onBookClick callback fires. It first checks for a slot-conflict (double booking), and if clear, calls renderPayPalModal.
2. The Modal & Payment (src/components/PayPalModal.js)
The modal slides in. When the user selects hours, the total dynamically updates. When they click the PayPal button, the SDK triggers a sandbox payment and calls the onApprove callback.
3. Persistence (src/utils/storage.js)
Inside onApprove, the app generates a random booking ID and pushes the new trip object into the travgod_bookings array using Storage.set(). The UI then updates to the "Booking Confirmed" screen.

To Change This, Start Here:

  • To modify AI Matching weights: Edit src/utils/aiMatch.js.
  • To change app colors or styling: Edit CSS variables at the top of src/styles/main.css.
  • To add more Mock Guides or Scams: Edit the constants in src/data/mockData.js (if separated, or top of DashboardView.js).
  • To clear your bookings during testing: Open DevTools (F12) > Application > Local Storage > clear travgod_bookings.
A Practice to Reuse:
During this project, we built a slot-conflict guard (in DashboardView.js) that checks LocalStorage before ever showing the payment screen. This is a great reusable pattern for future apps: always validate state and edge cases before handing the user off to a third-party checkout flow. It prevents confusing errors and double-charges!
